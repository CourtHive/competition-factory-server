# Admin Account Setup & Recovery

## Quick Reference

```bash
# List all users
pnpm admin:list

# Create a new superadmin
pnpm admin:create -e admin@example.com -p yourpassword

# Reset a forgotten password
pnpm admin:reset-password -e admin@example.com -p newpassword
```

> **Prerequisite:** PostgreSQL must be running (see **Storage / PostgreSQL Setup**).

## First-Time Setup

### 1. Start the database

```bash
# PostgreSQL — see Storage / PostgreSQL Setup
brew services start postgresql@17
```

### 2. Create your admin account

```bash
pnpm admin:create -e admin@yourorg.com -p your-secure-password
```

This creates a user with roles `[superadmin, admin, client]` — full access to all server features.

### 3. (Optional) Associate with a provider

```bash
pnpm admin:create \
  -e admin@yourorg.com \
  -p your-secure-password \
  --provider-id your-provider-uuid
```

### 4. Start the server and log in

```bash
pnpm watch
```

## Logging In

CFS does not log anyone in. Login, sessions, password and magic-link flows and user administration belong to the identity provider, **courthive-hiveid** (`:3140` locally; in production nginx routes `/auth/*` and `/account/*` to it). CFS verifies the tokens it issues. Create an account with the admin script above and sign in through hiveid; `Mentat/scripts/local/seed-local.mjs` seeds a full local cast the same way.

There is no built-in development account any more: the old `axel@castle.com` login lived in CFS's own login path and went with it.

## Password Recovery

```bash
# 1. Verify the user exists
pnpm admin:list

# 2. Reset their password
pnpm admin:reset-password -e admin@yourorg.com -p new-secure-password
```

Passwords are stored as bcrypt hashes (10 salt rounds).

## CLI Reference

```
node src/scripts/admin-user.mjs <command> [options]

Commands:
  list                                    List all users with roles
  create   -e <email> -p <password>       Create a superadmin user
           [--provider-id <id>]
  reset-password  -e <email> -p <password>  Reset password
  set-roles  -e <email> -r <roles>        Set roles (comma-separated)

Options:
  -e, --email                      User email address
  -p, --password                   Password (plain text, will be hashed)
  -r, --roles                      Comma-separated role list
  --provider-id                    Provider/organization ID
```
