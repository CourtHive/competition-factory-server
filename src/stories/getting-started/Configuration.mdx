# Configuration

All configuration is via environment variables in the `.env` file. The server uses `dotenv` to load these at startup.

> **Important:** `dotenv` does **not** override environment variables already set in your shell. If a variable like `PG_USER` is exported in your shell profile, that value takes precedence over `.env`.

## CMX operator reads and scores

Set `OPERATOR_MATCH_ENABLED=true` on a CFS instance serving the CMX candidate. The default is off.
The named `POST /operator/match` route needs the matching server-side factory DTO candidate. CMX sends
four identifiers and an admin-audience user session. CFS checks a live scoped scoring grant, reads the
committed record and returns the minimized match and its opaque revision.
`POST /operator/score` takes the target, result intent, score dialog outcome and stable command ID.
Corrections require the reviewed revision. A lost acknowledgement is retried with the same command and ID.
Scoring shares HTTP mutation delivery, including durable receipts, notices and cache invalidation.
SQL projection delivery continues to use its existing outbox configuration.

Under the same flag, `POST /operator/catalogue-access` evaluates up to 101 candidate tournament IDs for the
verified caller and returns the permitted IDs. Query calls this route for catalogue pages and individual day lists.
Official scoring always checks current tournament access, assignment role and provider policy through the CFS
mutation gate, even on deployments using legacy unscoped reads. The catalogue additionally requires a live
tournament-wide scoring grant. CFS repeats authorization on match reads and submissions.
For each nonempty batch CFS loads the subject’s assignments once and reads the subject’s grants for the selected
provider and candidate IDs in one query. It then checks ownership and mutation policy for each covered tournament.
An authorized administrator or assigned scorer can still use ordinary CFS scoring without a grant, or score within
a court-level grant, while this catalogue omits the tournament. Named operator match and score calls require a
live grant covering the particular match.

## Public Metrics

<table>
  <thead>
    <tr><th style={{ textAlign: 'left' }}>Variable</th><th style={{ textAlign: 'left' }}>Default</th><th style={{ textAlign: 'left' }}>Description</th></tr>
  </thead>
  <tbody>
    <tr><td><code>PUBLIC_METRICS_LOG</code></td><td><code>false</code></td><td>Set to <code>true</code> to enable detailed logging of public namespace connections, room joins/leaves, and periodic usage summaries</td></tr>
    <tr><td><code>PUBLIC_METRICS_INTERVAL</code></td><td><code>60000</code></td><td>Interval in milliseconds between periodic metrics summaries (default: 1 minute)</td></tr>
  </tbody>
</table>

When enabled, the server logs structured entries for each connect, disconnect, join, and leave event on the `/public` namespace, including client IP, user-agent, and origin. A periodic summary reports total connected clients and per-tournament room occupancy. See [Public Notifications](?path=/docs/architecture-public-notifications--docs) for details.

## Example `.env`

```env
APP_NAME='Competition Factory Server'
APP_MODE='development'
APP_PORT='8383'

JWT_SECRET='replace-with-a-truly-random-string'
JWT_VALIDITY='2h'

STORAGE_PROVIDER=postgres

PG_HOST=localhost
PG_PORT=5432
PG_USER=courthive
PG_PASSWORD=
PG_DATABASE=courthive

REDIS_URL=redis://localhost:6379
REDIS_TTL=28800000
```
